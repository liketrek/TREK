# TREK v5.2.0 integration

The local feature branch `codex/upgrade-trek-v5.2.0` starts at fork dev `e57b3b96c009bed5834d037fd2932cf49b6faeac`. Merge `7604a9666bba0a237045e8d8d70989e0902b4ffb` retains both fork history and the official v5.2.0 commit `8809654a43fe718605c03530bd78367f431719ea`. The official tag and commit are unsigned. On 2026-11-24 the maintainer confirmed the release and requested local integration after reviewing its provenance. Core packages are 5.2.0 and the plugin SDK is 1.10.0. [Official release](https://github.com/liketrek/TREK/releases/tag/v5.2.0) · [Pre-implementation assessment](v5.2.0-assessment.md)

## Changes for travelers

| Feature | Integrated behavior |
| --- | --- |
| Costs | The selected display currency applies to debts and repayments. Each expense first uses its saved rate for the currency pair, then the trip rate, then the system rate. Confirming a repayment uses the displayed quote. Historical payments keep their recorded values. |
| Visit duration | Road Trip uses the upstream per-visit editor. The regular itinerary also edits that visit's duration. Both support zero through 10,080 minutes. The trip PDF retains the timing projection in the upstream layout. |
| Dashboard and sessions | The desktop and mobile dashboards use the upstream trip-date display. The exact departure countdown was removed. Remembered login on the fork's deployment remains 30 days. |
| Other fork features | Ordered common currencies, guest identity transfer, mobile day-selection recovery, Hong Kong Traditional Chinese, and the fork's Legal and Source information are carried forward. The fork keeps its Lightsail pipeline and optional Sonar check. |

## Database upgrade

Existing SQLite migration files retain their original content. Migration `20200101046510` widens the fork's old stay-duration constraint while preserving its values. The PostgreSQL baseline includes the fork ledger and historical Web Push data. A transactional adoption script brings a populated upstream PostgreSQL schema into the fork. SQLite remains supported.

## Verification

- An unmodified checkout of v5.2.0 built successfully and passed all 2,839 shared tests.
- The integrated plugin SDK passed 445 tests and its type checks. Eight tests were skipped. The fork's CI scripts passed 120 tests and the GitOps scripts passed 21.
- The storage adapter passed all 21 contract tests against MinIO's official release image.
- On PostgreSQL 18, an upstream database seeded with a trip, financial data, and a push subscription was upgraded and booted twice. The seeded records survived, the named fork migration receipts were present, and the schema matched the fork baseline.

- A populated candidate SQLite database was moved to PostgreSQL 18. The mover verified counts and checksums. Its encrypted historical Web Push record, saved expense rate, seven-day stay and five fork receipts survived two startups. Legacy SQLite upgrades were exercised separately.

## Deployment evidence

Local fixtures exercise migration paths and repeat startup. Production promotion still requires rehearsing restoration from a recent backup, checking installation-specific plugins, and verifying the deployed configuration and encryption material.
